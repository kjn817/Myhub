# MyHub Phase 4D — 백업·복원 설계

## 1. 백업 범위

### D1 데이터
| 테이블 | 백업 대상 | 비고 |
|--------|-----------|------|
| memos | ✅ 전체 | 잠금 메모 포함 (암호화 상태 유지) |
| ai_memory | ✅ 전체 | 기존 legacy 기억 |
| ai_memory_v2 | ✅ 전체 | is_active=0 포함 (보관된 기억) |
| schedules | ✅ 전체 | |
| todos | ✅ 전체 | |
| ai_settings | ✅ 전체 | memory.* 플래그 포함 |
| ai_feedback | ✅ 전체 | |

### FTS 인덱스
- `memos_fts`, `ai_memory_fts`: **백업 제외** (재생성 가능)
- 복원 시 원본 테이블에서 재구성

### 제외 항목
- `ai_memory_fts`: 재생성 가능하므로 백업 불필요
- 세션 데이터: 휘발성

## 2. 기존 ai_memory 데이터 보존

- 운영 현재 0건, 향후 증가 가능
- 백업 시 원본 그대로 보존
- 복원 시 덮어쓰지 않고 병합 (ID 충돌 방지)

## 3. FTS 원본과 인덱스 복구 방식

### 백업
- 원본 테이블만 백업 (`ai_memory_v2`)
- FTS 테이블은 백업 제외

### 복원
1. 원본 테이블 복원
2. FTS 테이블 재생성:
   ```sql
   -- 기존 FTS 삭제 후 재생성
   DROP TABLE IF EXISTS ai_memory_fts;
   -- 0028 마이그레이션의 CREATE VIRTUAL TABLE 재실행
   -- 트리거는 자동 재생성됨
   ```
3. `integrity-check`로 검증

### 주의사항
- 비활성(`is_active=0`) 기억은 FTS에 인덱싱되지 않음 (트리거 조건)
- 복원 시 트리거가 자동으로 올바른 상태 반영
- **절대 수동으로 FTS에 직접 INSERT 금지**

## 4. 비활성·영구 삭제 기억의 백업 정책

| 상태 | 백업 | 복원 |
|------|------|------|
| is_active=1 | ✅ 포함 | ✅ 복원 |
| is_active=0 (보관) | ✅ 포함 | ✅ 복원 (보관 상태 유지) |
| 영구 삭제됨 | ❌ 제외 | N/A |

**이유**: 보관된 기억은 사용자가 복원할 수 있어야 함. 영구 삭제는 의도적 제거이므로 백업 제외.

## 5. Time Travel 전체 DB 복원 위험

### 위험
- Time Travel 복원은 **전체 DB를 특정 시점으로 되돌림**
- 복원 시점 이후의 모든 신규 데이터 손실
- 예: 10/11 14:00에 복원 → 14:00 이후 생성된 메모·기억 모두 삭제

### 대응
- **자동 실행 금지**: 반드시 사용자 승인 필요
- 복원 전 현재 데이터 백업 (별도)
- 영향 범위 사전 보고 (손실될 데이터 목록)
- 복원은 최후 수단으로만 사용

## 6. 복원 시 신규 데이터 손실 방지

### 절차
1. 복원 전 현재 DB 전체 백업
2. 복원 실행 (승인 후)
3. 백업에서 복원 시점 이후 데이터 추출
4. 수동 병합 (충돌 시 사용자 판단)

### 기술적 한계
- D1 Time Travel은 테이블 단위 복원 미지원 (전체 DB만)
- 자동 병합 불가 → 수동 작업 필요

## 9. 백업·복원 실패 시 중단 및 복구 절차

### 백업 실패
1. 즉시 중단
2. 오류 로그 기록
3. 부분 백업 파일 삭제 (불완전한 백업 사용 금지)
4. 사용자에게 보고

### 복원 실패
1. 즉시 중단 (추가 쓰기 금지)
2. 현재 상태 보존
3. Time Travel 복원 검토 (승인 필요)
4. 사용자에게 영향 범위 보고

### 공통 원칙
- 실패 시 임의 재시도 금지
- 원본 데이터 우선 보호
- 모든 작업 로그 기록

## 10. FTS 재구성 시 개인정보 주의

### 위험
- FTS 재구성 시 비활성/잠금 데이터를 잘못 인덱싱할 수 있음

### 방지책
1. 트리거 조건 재확인:
   - `ai_memory_v2`: `is_active=1`만 인덱싱
   - `memos`: 잠금 및 sensitivity>=2 제외 (0026 조건)
2. 재구성 전 트리거 SQL 검토
3. 재구성 후 샘플 검색으로 제외 확인
4. **절대 `INSERT INTO ... SELECT *`로 무조건 복사 금지**

### 검증 쿼리
```sql
-- 비활성 기억이 FTS에 없는지 확인
SELECT COUNT(*) FROM ai_memory_fts WHERE rowid IN (
  SELECT id FROM ai_memory_v2 WHERE is_active = 0
);
-- 0건이어야 함
```

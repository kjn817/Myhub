# MyHub 68차 기술 검토 요청 — 에코 아키텍처 근본 재설계

## 1. 현재 상황 (2026-10-13 22:00 KST)

### 67차까지의 시도와 결과

| 차수 | 시도 | 결과 |
|---|---|---|
| 61차 | 원문 참조형 생성 (6개 도구) | 생성 성공, 안정적 |
| 63차 | 도구 9개로 확장 + memo_format | 심각한 회귀 (생성 6회 연속 실패) |
| 63차 긴급 | memo_format 제거 | 생성 복원 |
| 65차 | memo_format A안 + 문맥 저장소 (10개 도구) | 생성만 성공, 수정/꾸미기/열기 실패 |
| 67차 | 문맥 읽기 + trace 로깅 + 위젯 localStorage | 문맥 저장 확인, 도구 호출 여전히 실패 |

### 핵심 관찰

1. **도구가 6개일 때는 안정적**이었음
2. **도구를 늘릴수록 불안정**해짐 (9개→실패, 10개→실패)
3. **Llama 3.3 70B가 복잡한 Function Calling을 처리하지 못함**
4. **문맥 저장소는 동작**하지만 (D1에 저장됨), 모델이 활용하지 못함
5. **"ID가 숫자가 아니다"** 같은 거짓 핑계는 모델의 환각

## 2. 근본적인 문제 제기

### 문제 1: LLM에게 너무 많은 것을 맡김

현재 에코는 다음을 모두 LLM이 결정합니다:
- 어떤 도구를 호출할지 (10개 중 선택)
- 인자를 어떻게 구성할지
- "방금 만든 메모"가 무엇을 의미하는지
- UI를 열고 닫을지

Llama 3.3 70B는 이 복잡도를 안정적으로 처리하지 못합니다.

### 문제 2: 대화가 쌓이는 구조

- 위젯: localStorage로 대화 ID 유지 (방금 적용)
- 메인 채팅: 대화 목록에서 선택
- 문제: 대화가 무한히 쌓이고, 어떤 대화에 문맥이 있는지 알 수 없음

### 문제 3: 위젯과 메인 채팅의 기능 격차

- 위젯: 대화 목록 없음, 삭제 불가, 요약 없음
- 메인 채팅: 대화 목록 있음
- 위젯이 "서브 AI"로서 제대로 동작하지 못함

## 3. 제안하는 아키텍처

### 3.1 도구 축소 (10개 → 4개)

**유지:**
- `memo_create_from_source` (생성 - 원문 참조형)
- `memo_search` (검색)
- `memo_get` (조회)
- `memo_delete` (삭제)

**제거하고 UI로 대체:**
- `memo_update` / `memo_update_from_source` → 위젯의 "편집" 버튼
- `memo_format` → 위젯의 서식 툴바
- `memo_open` / `memo_close` → 위젯이 직접 패널 제어

**이유:**
- 수정/꾸미기/열기/닫기는 LLM을 거칠 필요가 없음
- 사용자가 "이 메모 수정해줘"라고 하면 위젯이 바로 편집 모드로 전환
- LLM은 "무엇을" 할지만 결정하고, "어떻게"는 UI가 처리

### 3.2 대화 모델 변경 (축적 → 단일 작업 대화)

**현재:** 대화가 쌓임, 어떤 대화에 문맥이 있는지 모름

**제안:**
- 사용자당 1개의 "에코 작업 대화"만 유지
- 새 요청이 오면 기존 대화에 추가
- 일정 길이 초과 시 자동 요약 후 압축
- "새 대화" 버튼으로 명시적 초기화
- 위젯과 메인 채팅이 같은 대화 공유 (선택적)

**구현:**
```sql
-- 사용자당 1개의 활성 에코 대화
SELECT id FROM ai_conversations
WHERE title = '에코 작업 대화'
ORDER BY updated_at DESC LIMIT 1
```

### 3.3 위젯 기능 강화

**추가:**
- 대화 기록 보기 (접기/펼치기)
- "대화 지우기" 버튼
- 메모 요약 버튼 ("이 메모 요약해줘")
- 빠른 액션: [편집] [꾸미기] [삭제] 버튼을 에코 응답에 포함

**예시:**
```
사용자: "방금 만든 메모 보여줘"
에코: [메모 내용 표시]
     [편집] [굵게] [불릿] [삭제]
```

### 3.4 메모 요약 기능

**새 도구:**
- `memo_summarize(id)` → 서버에서 LLM 호출 없이? 아니면 별도 요약 모델?

**질문:** 요약은 에코(Llama)가 직접 해야 하는가, 아니면 별도 경량 모델?

## 2. knip 설정 (`knip.json`)과 제외 사유

```json
{
  "$schema": "https://unpkg.com/knip@6/schema.json",
  "entry": [
    "src/index.ts", "src/scheduled.ts", "src/modules.ts",
    "public/**/*.js",
    "gemini-relay/main.ts",
    "scripts/*.mjs",
    "tests/evals/*.cjs",
    "tests/sec-001-test.cjs",
    "tests/worker/*.ts"
  ],
  "ignore": ["*.test.js", "*-bundle.cjs", ".scratch/**"],
  "ignoreDependencies": ["jsdom"],
  "ignoreExportsUsedInFile": true
}
```

### entry (정적 import 그래프에 안 잡히는 진입점)

| 패턴 | 사유 |
|---|---|
| `src/index.ts`, `src/scheduled.ts`, `src/modules.ts` | Worker 진입점 + 모듈 레지스트리 |
| `public/**/*.js` | HTML `<script src>`로 로드되는 브라우저 JS. `public/js/memo/*.js`는 `scripts/build-memo-bundle.sh`가 `public/js/memo-bundle.js`로 이어붙이는 원본이라 import 그래프에 안 잡힌다 |
| `gemini-relay/main.ts` | Deno Deploy용 별도 진입점 (import 없음, `Deno.serve` 단독 실행) |
| `scripts/*.mjs` | 수동 실행 스크립트 (`create-test-session.mjs`, `test-worker-search.mjs`) |
| `tests/evals/*.cjs` | promptfoo YAML(`promptfooconfig*.yaml`)에서 `file://./mock-provider.cjs`, `file://./myhub-provider.cjs`, `file://./assertions.cjs:checkNewsFreshness`로 참조 — knip은 YAML 참조를 못 본다 |
| `tests/sec-001-test.cjs`, `tests/worker/*.ts` | 수동 실행 테스트 스크립트/Worker (jest `testMatch` 밖) |

### ignore (분석 대상이 아닌 것)

| 패턴 | 사유 |
|---|---|
| `*.test.js` (루트만) | 루트 레거시 phase 테스트 40건. jest `testMatch`는 `tests/**`만 보므로 실행되지 않는다 (8절 별도 목록). `*.test.js`는 슬래시가 없어 루트 파일에만 매칭된다 |
| `*-bundle.cjs` (루트) | esbuild 산출물 12건 (추적 불가한 생성 파일). 일부는 `.gitignore`에도 있다 |
| `.scratch/**` | 일회용 실험 스크립트 디렉토리 |

제거한 무시 항목 (knip 힌트로 확인해 삭제): `src/index-inline.ts`·`coverage/**`는
`.gitignore`/`tsconfig exclude`로 이미 제외되고, `skills/**`는
`ignoreExportsUsedInFile` 적용 후 보고할 항목이 없어져서 무시 목록이 불필요해졌다.
`jscpd`·`madge`도 `ignoreDependencies`에서 뺐다 — `lint:circular`·`lint:duplication`
스크립트가 바이너리를 직접 호출하므로 knip이 사용 중으로 인식한다.

### ignoreDependencies / ignoreExportsUsedInFile

- `jsdom`: 직접 import·`@jest-environment jsdom` 지정이 전혀 없다
  (jest 설정은 `testEnvironment: 'node'`). `jest-environment-jsdom`의 전이 의존성으로만 존재.
  `jest-environment-jsdom` 자체도 사용처가 없어 함께 제거 후보이나, knip이 플래그하지 않아
  8절에 수동 확인 항목으로 남겼다.
- `ignoreExportsUsedInFile: true`: **가장 큰 오탐 원인 제거**.
  설정 없이 돌리면 "같은 파일 안에서만 쓰는 export"가 79건 중 대부분을 차지한다
  (예: `MEMORY_CITATION_RE`, `SESSION_TTL_MS`, `GOOGLE_AUTH_URL` — 정의 파일 내부에서만 사용).
  knip은 다른 파일에서 import하지 않으면 미사용으로 보므로, 파일 내부 사용분은 무시하도록 했다.
  이 옵션을 켜면 남는 것은 진짜 미사용 export와 불용 re-export뿐이다.

## 8. knip 범위 밖 별도 목록 (설정에 안 넣은 것 — 판단 필요)

### 8-1. 루트 레거시 테스트 40건 — jest에서 실행되지 않음

루트 `*.test.js` 40건(`phase1b.test.js` ~ `phase3d.test.js`, `ai.test.js`, `chat.test.js`,
`editor.test.js` 등)은 jest `testMatch`(`tests/**`만)에 안 걸려 CI에서 실행되지 않는다.
이들이 참조하는 `/tmp/*-test.cjs` 픽스처는 테스트 실행 시 생성되는 휘발성 파일이다
(4절의 unresolved imports 변동 원인). **아카이브(`tests/legacy/` 이동 또는 삭제) 여부를
사람이 결정할 것.** `editor-functions.js`(루트)도 이 레거시 테스트(`editor.test.js`)만
참조하므로 함께 판단한다.

### 8-2. 루트 esbuild 번들 12건 — 생성 산출물

`ai-bundle.cjs`, `ai-routes-bundle.cjs`, `briefing-bundle.cjs`, `orch-bundle.cjs`,
`push-bundle.cjs`, `recurrence-bundle.cjs`, `router-bundle.cjs`, `sched-tools-bundle.cjs`,
`schedule-bundle.cjs`, `todo-bundle.cjs`, `todo-tools-bundle.cjs` + `public/js/memo-bundle.js`.
일부는 `.gitignore`에 있으나 tracked 상태라 저장소에 남아 있다.
재생성 가능한 산출물이므로 추적 해제 여부를 별도 결정할 것
(`public/js/memo-bundle.js`는 `deploy_full.py`가 배포 시 재생성한다).

### 8-3. `jsdom` + `jest-environment-jsdom` — 제거 후보 (수동 확인 필요)

knip은 `jsdom`만 미사용 devDependency로 봤다. `jest-environment-jsdom`은 knip이
플래그하지 않았으나, 코드·설정 어디에도 jsdom 환경 지정이 없다
(`jest.config.js`는 `testEnvironment: 'node'`, `@jest-environment jsdom` 주석 없음).
두 패키지 모두 제거 후보이나, Playwright E2E(`tests/e2e/`)가 jsdom에 의존하는지
최종 확인 후 삭제할 것. **이 트랙에서는 삭제하지 않았다.**

## 10. 재실행 방법

```bash
npm run lint:deadcode    # knip --no-progress (exit 1 = findings 있음)
npm run lint:circular    # madge --circular --extensions ts src (exit 1 = 순환 있음)
npm run lint:duplication # jscpd --min-tokens 50 --format typescript src (리포트만, exit 0)
npx tsc --noEmit         # knip/madge/jscpd 도입과 무관하게 항상 통과해야 함
```

- 새 진입점(HTML 참조 JS, promptfoo provider, 수동 스크립트, Deno 진입점)이 생기면
  `knip.json`의 `entry`에 추가할 것. 추가하지 않으면 미사용 파일로 오탐된다.
- `knip --fix` 사용 금지. 목록만 내고 사람이 판단한다.
- knip이 간헐적으로 다른 결과를 내면 4절의 오탐 4건(`trace-viewer`, `isValidTraceId`,
  `isValidSpanId`, `getFactTemporalEdges`)부터 grep으로 대조할 것.

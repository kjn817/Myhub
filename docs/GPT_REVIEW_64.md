## 2. 심각한 회귀 발생 (64차 핵심 이슈)

### 증상

`71dcb20` 배포 후 브라우저 테스트에서 다음이 발생했습니다.

- 메모 생성 6회 연속 실패 (61차에서는 정상 동작)
- 메모 검색 실패 (존재하는 메모를 찾지 못함)
- 메모 꾸미기/수정 실패 (메모를 특정하지 못함)
- 에코 응답에 "最近" (일본어/중국어 한자) 혼용
- 환각: 존재하지 않는 "integration 테스트 메모" 언급

### 원인 분석

`memo_format` 도구의 파라미터 구조가 문제였습니다.

```typescript
operations: {
  type: 'array',
  items: {
    type: 'object',
    properties: {
      type: { type: 'string', ... },
      enabled: { type: 'boolean', ... }
    },
    required: ['type']
  }
}
```

Workers AI (`@cf/meta/llama-3.3-70b-instruct-fp8-fast`)의 Traditional Function Calling이
중첩된 배열-객체 구조를 제대로 처리하지 못하고 모델을 혼란시킨 것으로 추정됩니다.

도구 개수도 61차 6개 → 63차 9개로 증가했습니다.

### 긴급 조치 (커밋 `bde217d`, 배포 완료)

- `memo_format` 완전 제거 (도구 정의, Dispatcher, 실행 함수, 프롬프트 참조)
- `FCToolDefinition` 인터페이스를 단순 구조로 복원
- 재배포 후 브라우저 검증: 메모 생성 복원 확인 (ID 174, 한글 정상)

## 4. GPT에게 질문

### Q1. memo_format을 어떻게 다시 설계해야 하는가?

제약 조건:
- Workers AI가 중첩 배열-객체를 처리하지 못함
- AI가 직접 마크다운/HTML을 생성하면 한글 변형 위험 (59차 문제)
- 서버가 원본에 서식을 적용해야 함

후보안:
- **A안**: 단순 문자열 enum 파라미터 (`format_type: "bold_title" | "bullet_list" | "quote" | "clear"`) — 한 번에 하나의 서식만
- **B안**: 여러 boolean 플래그 (`bold_title: boolean, bullet_list: boolean, ...`) — 단순하지만 확장성 낮음
- **C안**: 꾸미기 기능을 완전히 포기하고 수동 편집으로 안내

어떤 방식이 Workers AI 호환성과 기능 완성도 사이에서 최선인가?

### Q2. 도구 개수를 줄여야 하는가?

현재 8개 도구입니다. 61차(6개)는 안정적이었고, 63차(9개)는 깨졌습니다.
`memo_update`와 `memo_update_from_source`를 하나로 합치는 것이 나은가?
아니면 현재 8개 구조를 유지해도 되는가?

### Q3. "방금 만든 메모" / "그 메모" 문맥 참조

62차에서 서버가 최근 작업 ID를 보존하라고 권고했습니다.
현재 구현에는 대화 상태 저장소가 없습니다.

질문:
- Workers AI 호출마다 `conversationId`를 전달하고 있는데, 서버에서 이를 키로 사용해 최근 도구 실행 결과를 메모리에(또는 D1에) 저장하는 방식이 적절한가?
- 아니면 프롬프트에 "직전 도구 결과를 참조하라"는 지시만으로 충분한가?
- D1에 저장한다면 어떤 테이블 구조를 권장하는가?

### Q4. 검색 실패의 근본 원인

- "'재테스트' 메모 찾아줘" → 검색 실패 (본문에 "재테스트"가 없었음 - 사용자 요청과 실제 저장 내용 불일치)

이것은 FTS5 토큰화 문제인가, 아니면 모델의 키워드 추출 문제인가?

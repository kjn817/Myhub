## 2. 핵심 문제: 도구가 호출되지 않거나 실패함

### 증상 분석

모델이 명시적 ID(175)를 받았는데도:
1. `memo_format` → "실패했습니다" (이유 불명)
2. `memo_update_from_source` → "ID가 숫자가 아니다" (거짓말, 175는 숫자)
3. `memo_open` → "열 수 없습니다" (이유 불명)

이는 세 가지 가능성을 시사합니다:

**가설 A: 모델이 도구를 호출하지 않고 텍스트로 거짓 응답 생성**
- 모델이 Function Calling을 건너뛰고 "실패했습니다"라고 직접 답변
- "ID가 숫자가 아니다" 같은 핑계는 모델의 환각

**가설 B: 서버 Dispatcher에서 도구가 거부됨**
- `executeMemoGet`의 권한/잠금 검사가 실패
- ID 175의 메모가 `is_locked=1`이거나 `sensitivity>1`인가?
- `ai-access.ts`의 `searchAccessibleMemos`가 아닌 직접 조회 경로의 문제?

**가설 C: 도구 정의가 모델에게 제대로 전달되지 않음**
- 10개 도구가 너무 많아 모델이 혼란
- `memo_format`의 `enum`이 Workers AI에서 지원되지 않음

### 확인된 사실

- ID 175 메모는 D1에 존재함 (목록에 표시됨)
- 생성은 동작함 (같은 세션에서 ID 175 생성 성공)
- 닫기는 동작함 (uiAction 반환 구조)
- 열기/꾸미기/수정이 실패함

### 아직 확인하지 못한 것

- 모델이 실제로 `tool_calls`를 반환했는지 (서버 로그 필요)
- Dispatcher가 어떤 에러를 반환했는지
- ID 175의 `is_locked`, `sensitivity` 값
- `executeMemoGet`이 ID 175에 대해 무엇을 반환하는지

## 3. 문맥 저장소 미동작

"방금 생성한 메모의 ID가 몇 번이야?" → "최근에 생성한 메모가 없습니다."

가능한 원인:
1. 위젯 수정(75dc659)이 테스트 시점에 배포되지 않음 (배포는 21:43, 테스트는 21:43-21:45)
2. `callSingleAssistant`의 `options.conversationId`가 실제로 전달되지 않음
3. `updateMemoContext`가 실패하고 있음 (조용히 무시됨)
4. D1 테이블이 운영에 없음 (마이그레이션은 적용했다고 보고됨)

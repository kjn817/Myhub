# MyHub 62차 기술 자문 요청 (GPT용) — 위젯 메모 기능 완성

## 1. 현재 상태 (61차 완료)

### 동작 확인됨
- `memo_create` / `memo_create_from_source`: 한글 깨짐 없이 생성 성공 (ID 169·170·171)
- 원문 참조형 구조: 모델이 한글을 재생성하지 않고 서버가 원본에서 추출

### 구현됐으나 미검증
- `memo_open` / `memo_close`: 도구와 위젯 UI 연동 코드 구현됨, 브라우저 테스트 안 됨
- `memo_update`: 도구 존재, 위젯 경로로 테스트 안 됨
- `memo_search`: FTS5 기반, 키워드 추출 프롬프트 개선됨, 재테스트 필요

### 미구현
- `memo_format` (꾸미기): 도구 자체가 없음

### 알려진 문제
- `memo_close`: 열린 패널이 없는데도 "닫았습니다"라고 응답하는 거짓 성공 발생
  → 프롬프트에 "닫기 요청을 전달했습니다" 표현 안내 추가, 위젯에서 실제 닫힌 패널 없으면 안내 메시지 추가
  → 재배포됨, 재검증 필요
- `dataChanged`: FC 경로의 플래그가 마커 처리 코드에 의해 덮어씌워지던 버그 수정됨
  → 재배포됨, 재검증 필요

## 2. GPT에게 질문

### Q1. memo_format 설계

사용자 요구: "메모도 꾸미고" — 제목 굵게, 불릿 목록, 인용 등 서식 적용

제안하는 도구:
```
memo_format({
  id: number,           // 메모 ID
  formatting: {         // 적용할 서식
    bold_title: boolean,
    bullet_list: boolean,
    // ... 기타 서식
  }
})
```

질문:
1. 서식을 구조화된 파라미터로 받는 것이 나은가, 아니면 마크다운 텍스트로 받는 것이 나은가?
2. AI가 직접 HTML을 생성하도록 허용해도 되는가? (XSS 위험)
3. 기존 메모 내용과 서식을 어떻게 병합할 것인가? (전체 교체 vs 부분 적용)

### Q2. memo_update의 원문 참조 적용 여부

현재 `memo_update`는 모델이 새 텍스트를 직접 생성합니다:
```
memo_update({ id: 123, text: "새 내용" })
```

이것도 한글 변형 문제가 발생할 수 있습니다. `memo_create_from_source`처럼 원문 참조형으로 바꿔야 하는가?
- 예: `memo_update_from_source({ id: 123, source_text: "사용자 원문" })`

아니면 수정은 AI가 생성하는 것이 불가피하므로 다른 접근이 필요한가?

### Q3. 위젯 UI 액션의 보안 경계

현재 설계:
- `memo_open`: 서버가 메모 존재·권한 확인 후 `uiAction: 'open_memo'` 반환 → 위젯이 `openPane(id)` 호출
- `memo_close`: 서버가 `uiAction: 'close_memo'` 반환 → 위젯이 `closePane(id)` 호출

질문:
1. 모델이 임의의 메모 ID를 열어보도록 지시할 수 있는가? (권한 검사는 서버에서 하지만, UI 액션 자체가 남용될 수 있는지)
2. 잠긴 메모에 대한 `memo_open` 요청은 어떻게 처리해야 하는가? (현재 `executeMemoGet`이 잠금 검사 수행)
3. 위젯이 서버의 `uiAction`을 무조건 신뢰해도 되는가?

### Q4. 검색 개선

현재 문제:
- 사용자가 "방금 만든 위젯테스트 메모 찾아줘"라고 하면 모델이 전체 구문을 검색어로 사용
- 프롬프트에 "핵심 키워드만 추출" 안내 추가함

질문:
1. 검색어 추출을 프롬프트에만 의존하는 것으로 충분한가?
2. 서버에서 검색어를 후처리(불용어 제거 등)해야 하는가?
3. "그 메모", "방금 만든 것" 같은 문맥 참조를 해결하려면 대화 기록을 어떻게 활용해야 하는가?

암호화 키 로테이션

새 키로 교체

잠긴 메모·블록·첨부와 Google 토큰을 새 암호화 키로 다시 암호화합니다.
새 키 값은 비밀번호 관리자에서 만든 값을 직접 붙여넣으세요. 값은 이 브라우저에서 서버로 한 번 전송될 뿐, 어디에도 저장되지 않습니다.
실행 후에는 대시보드 시크릿 교체까지 한 번에 마쳐야 합니다 — 교체 전까지 전환된 항목은 읽히지 않습니다.
항목기준 건수dry-run 건수대조
실행 직후 할 일 — 대시보드 시크릿 교체
  1. Cloudflare 대시보드 → Workers & Pages → myhub → Settings → Variables and Secrets
  2. MEMO_ENCRYPTION_KEY를 편집해, 방금 입력한 새 키 값으로 교체하고 Deploy
  3. 교체 후 확인: 메모 화면에서 잠긴 메모 1건을 열어(PIN step-up) 본문이 보이는지, Google 연동 상태가 정상인지 확인
교체가 늦어지면 — 상태와 알아채는 법
  • 현재 상태는 「전환 완료 · 시크릿 교체 대기」입니다. 교체가 몇 시간·며칠 늦어져도 암호문 데이터 자체가 깨지지는 않습니다 — 저장된 암호문은 그대로 있고, 교체만 마치면 다시 열립니다.
  • 다만 교체 전까지 전환된 잠긴 메모·첨부는 열리지 않고 Google 연동도 끊겨 보입니다. 잠긴 메모를 열었을 때 본문 대신 복호화 오류가 보이면, 교체가 아직 안 됐거나 대시보드 값이 다르다는 신호입니다.
  • 교체 대기 중에는 새 잠긴 메모를 만들지 마세요. 아직 구 키를 가진 Worker가 새 잠긴 메모를 구 키로 암호화하면 상태가 섞여 복구가 복잡해집니다.
문제가 생기면
  • 건수가 기준과 다르면 실행 버튼이 자동으로 막힙니다. 화면의 건수만 Claude에 알려주세요. 키 값은 채팅에 붙여넣지 마세요.
  • 대시보드 교체가 실패했거나 Deploy가 늦어지면, 위의 「교체 대기」 상태가 계속될 뿐 데이터가 더 망가지지는 않습니다. 대시보드에서 교체·Deploy를 다시 완료하면 됩니다.
  • 교체 후에도 잠긴 메모가 열리지 않으면: ① 먼저 비밀번호 관리자의 값과 대시보드 값이 완전히 같은지 대조하세요 (앞뒤 공백·줄바꿈 포함 — 붙여넣기 실수가 가장 흔한 원인입니다). 틀렸으면 같은 값으로 다시 저장·Deploy하세요. ② 값이 같은데도 열리지 않으면, 값을 더 바꾸지 말고 즉시 Claude에 알려주세요. 롤백(POST /api/key-rotation/rollback)은 임의로 실행하지 말고 Claude와 함께 docs/backup-restore.md §6.1 절차로만 진행합니다 — 잘못된 값으로 롤백하면 암호문이 그 값으로 다시 암호화돼 복구가 더 어려워집니다.
